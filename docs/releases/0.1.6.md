# ADHD 0.1.6 — 2026-10-07

지속적인 목표 실행과 기존 Obsidian 위키의 문맥·경험 기록을 연결합니다.
기존 인증·모델·effort·라우터·플러그인·사용자 설정과 검증·복구 관문을 유지합니다.

## 목표 실행

`/goal 원하는 결과` 또는 `$adhd-goal 원하는 결과`를 사용합니다. 내장 `/goal`이
일반 프롬프트 훅을 거치지 않으면 호스트가 제공한 실제 transcript의
`thread_goal_updated`를 읽습니다. Codex sessions 아래의 파일, 세션 ID,
workspace와 root 이벤트를 확인하고 한 번에 읽는 크기를 제한합니다.
다른 채팅, 자식 에이전트, 잘못된 경로·목표 데이터는 목표 권한으로 사용하지 않습니다.

현재 요청을 보존하고 구현·검사·수정을 계속합니다. 기본 round·시간·정체·누적 호출
제한은 goal에서 생략하되 begin 시 명시한 정책 제한, 동시 실행, 단일 작성자,
Astra 제한과 독립 승인 관문은 유지합니다. 목표 변경은 실제 사용자 turn으로 계약을
조정합니다. 호스트의 pause·clear·종료·complete만으로 미완료 결과를 승인하지 않습니다.
사용자의 중단과 실제 외부 한도·필수 자료·권한 문제는 중단 조건입니다.

## Obsidian 연결

[연결·운영 안내](../obsidian.md)에 설정, 명령, 구조 적용과 복구를 정리했습니다.
기존 vault와 `wiki_context.py`를 사용하며 새 검색 서버나 두 번째 parser를 설치하지 않습니다.
프로젝트별 기본 비활성 설정에서 읽기·privacy·쓰기 범위를 선택합니다.

- 작업 시작 전 필요한 노트·문단만 조회합니다. canonical ID, revision, 정책 epoch와
  인덱스 generation을 전달하고 위키 내용은 `source_data`로 취급합니다.
- 변경분을 SQLite에 반영하되 현재 파일과 정책을 매 조회에서 확인합니다. 중복 ID,
  경로 이탈, reparse point, 잘못된 metadata와 stale revision은 자료를 내보내지 않습니다.
- 모든 작업의 장문 기록 대신 결정·명시적 사용자 평가·재사용할 성공·반복 실패를
  선별합니다. 긍정·부정·혼합·미수집 평가와 기술 검증 결과를 별도로 기록합니다.
- 후보 검토와 적용을 분리하고 예상 revision·정확한 diff·중복 키·잠금·복구 ledger로
  동시 편집과 재전송을 처리합니다. 다섯 템플릿과 두 Bases 화면을 제공합니다.
- 성공 코드·문서는 commit·파일·hash·검사 참조로 보존합니다. 재현·회귀·비용·복구
  근거가 있는 후보만 controller가 절차로 채택합니다. CLI의 임의 채택은 거부합니다.
- 용량·중복·참조를 확인하고 검증된 종료 기록만 명시적으로 압축·복원합니다.
  활성·재개 가능한 작업과 알 수 없는 자료를 보호하며 원본 해제는 별도 선택입니다.

기존 archive backend를 출처와 hash가 있는 로컬 asset으로 포함하고, ZIP과 설치된
릴리스에 goal 스킬·위키 runtime·템플릿·schema·예시·안내를 함께 제공합니다.
500개 입력 제한을 초과한 미실행 batch 계획의 복구는 입력을 나누며 기존 요구사항·
검사·의존성·관문을 보존합니다. 이미 실행·승인한 계획에는 적용하지 않습니다.

## 검증 범위와 업그레이드

goal의 프롬프트·호스트 이벤트·명시적 제한·중단·독립 승인, 위키의 privacy·삭제·
revision·동시 적용·복구·절차·archive 경계와 배포 ZIP의 설치·후크 회귀 검사를 제공합니다.
실제 위키 엔진을 사용하는 검사는 `ADHD_TEST_WIKI_CONTEXT`로 해당 파일을 지정합니다.
엔진이 없는 환경에서 건너뛴 검사는 실제 vault 연동의 통과 근거가 아닙니다.

고정 36개 진단 query와 cold/warm 비교 도구는 실사용 대표성이나 속도 향상을 보장하지
않습니다. 전체 model token 계측이 없으면 기록·정제·재시도·자식 호출을 포함한 절감률은
미측정입니다. 압축의 논리적 바이트 감소를 실제 디스크 확보량으로 보고하지 않습니다.

기존과 같이 `python adhd.py upgrade`를 실행합니다. 관리 백업과 상태를 보존하며
모델 강제 이전이나 저장공간 자동 정리를 수행하지 않습니다. 열린 Codex 채팅은 이전
후크·역할 profile을 캐시할 수 있으므로 새 채팅에서 0.1.6을 로드합니다. 설치 파일 교체가
이미 열린 세션의 새로운 독립 승인이나 hook trust를 증명하지 않습니다.
