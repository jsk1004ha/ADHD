# ADHD 0.2.0

This release adds bounded working storage and cross-run project coordination.

- Native upgrades retain the current release and one verified current original
  backup by default. Active references and unique/modified/unknown originals are
  protected. Retention failure is reported after the committed upgrade.
- Owned scratch has process-identity, child and reference tracking, recovery sweep,
  volume reservations, bounded streaming copies and selected ZIP extraction reuse.
- Document inspection streams media hashes while preserving package/text evidence.
- Large-task dispatch uses project-wide resource claims and a single integration
  gate. Generation/capability checks reject stale or duplicate ownership.
- Cross-run inputs wait for current producer validation, propagate deletions,
  and preserve earlier changes. Failed writers release through a durable outbox.
- Integrated workers retain replay commits or changed-file patches instead of
  full working copies. Captures retain the latest logs per owner by default;
  reports, final artifacts, modified captures and explicit pins are preserved.
- Ordinary command and scratch runners own descendant lifetimes with Windows Job
  Objects or Linux process groups. Rule coordination needs no model calls; optional
  negotiation is bounded to two messages per conflict revision.

See [workspace storage](../workspace-storage.md) and
[project coordination](../project-coordination.md) for commands and supported host
boundaries. Existing native state remains v2 and installation records remain v3.
Existing host-denied deletion is not retried by these features. Measurements from
representative fixtures are not claims of whole-project token, RAM or time savings.

In a local paired fixture check, three fresh-process inspections per version of
a 32 MiB media package returned identical evidence; peak process RSS fell by
52.1%. Twenty owned-scratch cycles retained zero scratch payload bytes. These
figures describe those fixtures and do not measure physical disk reclamation.
