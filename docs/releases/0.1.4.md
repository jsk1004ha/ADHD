# ADHD 0.1.4 — 2026-10-04

이번 릴리스는 같은 0.1.3 기반에서 진행한 세 작업을 통합합니다.
대규모 작업 실행 계층, native 종료·진행·프로필·MCP 검증 개선,
7개 작업 흐름 스킬과 기존 스킬 우선 탐색을 함께 제공합니다.

## 대규모 작업과 공통 배치 검사

- 원문 요구와 버전에 연결된 SQLite DAG, 인터페이스 준비 상태,
  핵심 경로 우선순위와 소유권·임대 세대를 저장합니다.
- 관측된 CLI 프로세스를 격리된 Git 작업 공간에 배정합니다. 준비된 파트,
  공유 자원·호스트·정책·예산에 맞춰 동시성을 조절하며 지원 상한은 6명입니다.
- 직렬 통합 후 후보를 고정하고 실제 파일·Git 메타데이터·검사 영수증을
  대조합니다. 오래된 결과나 종료가 확인되지 않은 작업은 재배정하지 않습니다.
- 일반 작업도 제작 뒤 `batch`로 검사를 모을 수 있습니다. 실패 원인을
  확인해 묶어서 수정하고 실패·영향·핵심 검사만 충분히 재실행합니다.
  대규모 작업의 선언된 검사 계획은 수리 과정에서 약화할 수 없습니다.
- 영어 역할 계약은 필요한 원문 발췌를 보존합니다. Ponytail 기반 단순화
  지침은 요구 동작·검사·보안 조건을 유지하는 구현에 적용합니다.

## native 운영과 연결 검증

- 중단·취소·예산 소진 경로를 공통 종료 처리로 묶고 마지막 자식이
  종료하기 전까지 작성자 소유권을 유지합니다.
- 진행 판정은 실제 대상 변경, 요구·계획 완료와 신선한 검사 결과를
  사용합니다. 시간·출력·digest 변동만으로 진행을 인정하지 않습니다.
- `simple`, `standard`, `deep` 프로필로 계획·위임·검토 강도를 선택합니다.
  부모 모델·추론 강도와 명시적인 정책 설정은 보존합니다.
- MCP 등록, 의존성, 인증·통합, 연결, 성공한 읽기를 구분합니다.
  실제 probe는 별도 동의와 검토된 읽기 호출이 필요하며 결과는
  연결·실행 파일·자격 증명 식별 정보 및 유효 시간에 연결됩니다.

## 작업 흐름 스킬

`adhd-shape`, `adhd-challenge`, `adhd-decide`, `adhd-steer`,
`adhd-unblock`, `adhd-retro`, `adhd-optimize`를 추가합니다.
각 스킬은 현재 운영자에게 필요한 판단과 근거를 넘깁니다.
7개를 매번 실행하거나 별도 루프를 만드는 절차가 아닙니다.
같은 이름의 기존 사용자·프로젝트·플러그인 스킬은 배포 사본보다 우선합니다.

## 설치와 확인 범위

저장소에서 `python adhd.py upgrade`를 실행하면 관리 설치 기록과 파일 해시를
확인한 뒤 0.1.4 릴리스로 옮깁니다. 인증·선택 모델·라우터·플러그인·기존
설정은 보존하고 관리 파일 백업과 기존 상태를 유지합니다.
스킬·역할·후크를 새 세션에서 다시 불러와야 합니다. 후크 신뢰는 Codex의
실제 승인 절차를 따르며 설치기가 승인을 만들어 내지 않습니다.

App의 작업 디렉터리 상관관계가 없는 작성자에는 기존 단일 작성자 제한을
유지합니다. 여러 작성자의 병렬 실행은 관측 가능한 CLI 경로에서 수행합니다.
계정별 모델 접근, 실제 외부 MCP·OAuth 연결, 실행 중인 App의 새 후크 적용,
속도·토큰 절감률은 소스·로컬 fixture 시험만으로 증명되지 않습니다.

공개 ZIP은 허용된 파일 목록과 SHA-256 manifest로 구성합니다.
개인 검증 자료, 실행 상태, 인증 정보와 생성된 그래프는 포함하지 않습니다.
CI는 Windows·Ubuntu 및 Python 3.11·3.13 회귀 검사와 새 환경의
ZIP·CLI·설치·후크 smoke 검사를 수행합니다.

대규모 실행 명령과 수리·복구 방법은 [실행 안내](../large-tasks.md)를 참조하세요.
