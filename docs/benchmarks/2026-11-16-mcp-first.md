# MCP-first real-task comparison (2026-11-16)

The final artifacts retained quality, but MCP-first did **not** reduce tokens in
this observed task. This result supports keeping the local-script fallback when
an available MCP adds overhead.

## Task and controls

Two fresh executor agents independently produced a JSON and Korean Markdown
validation report from the same 12 frozen, real ADHD unittest logs (19,807 bytes).
Both used `gpt-5.6-sol` with medium reasoning, the same output contract and no
inherited parent conversation. The baseline used native shell/Python; the MCP
lane used Node REPL MCP/JavaScript. Efficient batching and concise output were
allowed in both lanes. Both delivered a runnable generator and checked its output.

## Observed usage

Counts came from each agent's final Codex rollout
`event_msg.token_count.info.total_token_usage`, including repair attempts.

| Metric | Baseline | MCP-first | MCP change |
| --- | ---: | ---: | ---: |
| Input tokens | 450,601 | 625,661 | +38.9% |
| Cached input tokens | 422,272 | 595,968 | +41.1% |
| Uncached input tokens | 28,329 | 29,693 | +4.8% |
| Output tokens | 6,354 | 7,784 | +22.5% |
| Total tokens, including cached input | 456,955 | 633,445 | +38.6% |
| Uncached input plus output | 34,683 | 37,477 | +8.1% |
| Tool calls | 10 | 14 | +40.0% |
| Wall seconds | 243.0 | 262.4 | +8.0% |

Cached input is a subset of input; reported reasoning is a subset of output.
These counts are not a currency or billing estimate. Parent setup/orchestration/
evaluation is excluded from this table and recorded separately in local evidence.

## Quality and failure observations

An independent oracle checked every JSON field and every row, all aggregate
counts, input SHA-256 preservation, Markdown file coverage and the historical
execution-count caveat. Both outputs passed and their JSON was semantically
identical: 1,396 historical test executions, 8 passed logs, 4 failed logs,
9 failures, 5 errors and 16 skips. These are counts from input logs, not newly
executed tests or a claim that all historical checks passed.

The MCP lane repaired a generated-script syntax error, a Node REPL `process`
compatibility issue and an escaping bug that initially classified all logs as
unrecognized. It corrected them before delivery. Those extra attempts remain in
the measured totals; no successful-only interval was selected.

## Interpretation

This is one A/B pair, not a statistical average. Tool protocol, implementation
language, agent choices, cache state and repairs all affect the comparison.
It does not isolate the intrinsic overhead of the MCP protocol itself.
A general code-execution MCP replacing an efficient local batch script did not
save tokens here. Dedicated MCP capabilities that reduce work or round trips
need their own measured comparison. The harness preference remains conditional
on suitability and efficiency; quality checks remain required.

Raw session transcripts, personal paths and original diagnostic logs remain local.
