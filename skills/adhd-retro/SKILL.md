# Convert outcome feedback into next actions

Read the actual final artifact, acceptance criteria, check/review results and human
feedback, not just an agent completion summary. For handoff and retention read
[the shared contract](../adhd-native/references/skill-handoff.md).

Separate the expected/actual difference into a contract violation, missing check,
new requirement or situation-specific preference. Technical claims should be
checked against the artifact; a user's taste is not disproved by passing tests.
State observed contributors separately from inferred causes, without blame.

Return two bounded products:

- **This result's repair:** affected artifact/owner, priority, concrete action and
  checkable completion condition, retaining unchanged requirements.
- **Future reference candidates:** a sourced lesson or preference with its task
  scope, exceptions and evidence; no universal rule inferred from one complaint.

Finish with the requested analysis. If repair was also authorized, hand contract-
preserving fixes to the current owner and real requirement changes to steer.
Do not overwrite the record of a completed run; use the actual new-request lifecycle.

Write long-term memory only if the human explicitly requests retention, following
the installed memory policy and scoped provenance. “This looks wrong” is not an
instruction to rewrite global preferences. Proposed lessons are not independently
verified procedures and cannot be inserted as controller-only successful records.

Example: “검증은 통과했는데 원문 열기가 불편해.” Inspect the interaction and
express the requested repair as an observable source-opening behavior; record
satisfaction separately from the prior technical checks.

## Method inputs

Adapt evidence/contributors/actionable follow-up from [Google SRE](https://sre.google/sre-book/postmortem-culture/)
and next-attempt feedback from [Reflexion](https://arxiv.org/abs/2303.11366).
The latter is research inspiration, not a measured ADHD improvement or permission
to retain private conversations.
